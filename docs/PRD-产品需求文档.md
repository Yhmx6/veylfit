# 映衣间 · Veylfit：PRD 产品需求文档

版本：0.1.0（仓库初始化）｜2026-11-12｜配套：[产品与技术方案](产品与技术方案.md)。

## 1. 用户、目标与范围

面向希望知道衣服穿在自己身上是否好看、适合什么场合的用户。第一阶段验证真实感照片试衣的闭环；用户决定审美目标，不仅凭性别、年龄或体重断定其想显瘦、显高或成熟。

MVP包含：档案采集、手绘外形选择、可选尺寸、正侧照片、后台体型、面部参考、三个人物底图候选、分项确认、衣物导入、一次试穿及结果回存。用户界面不展示白模，不要求所有测量，不加入肩颈滑杆。

非范围：医疗或体脂评价、精确尺码保证、真实布料仿真、社交发布、自动下单、无限制支持任意生图API。衣橱与自动搭配在后续阶段。

## 2. 用户流程与逐步要求

| 步骤 | 输入与交互 | 完成条件 |
| --- | --- | --- |
| 1 基本资料 | 性别、身高、体重、年龄 | 本人填写或明确确认；数值和单位有效 |
| 2 整体体型 | 偏胖/正常/偏瘦三张手绘示意 | 主动选择，自动进入下一步 |
| 3 四个部位 | 手臂→胸腹→臀腿→肩颈，各三选一 | 每步仅当前三卡；可上一步修改 |
| 4 补充尺寸 | 胸、自然腰、脐腹、臀围；肩宽、腿内长 | 可部分填或全部跳过；留空不是0 |
| 5 全身照片 | 正面、真正侧面各一张 | 同期体型，头脚完整，清晰可判读 |
| 6 体型处理 | 后台构建与必要纠错 | 失败给出原因，不让用户修复杂三维模型 |
| 7 面部参考与候选 | 适当补正脸及微侧面照，生成三张底图 | 用户逐项检查脸与体型，选择最接近自己的候选 |
| 8 固定人物 | 形成已确认正面/斜侧参考 | 保存版本，关键输入改变后重新确认 |
| 9 导入衣物 | 单品图、整套穿搭参考图 | 用户确认要试的衣物，区分衣服与原模特 |
| 10 试穿与回存 | 场景、风格、自然姿态表情 | 结果归属正确版本，认可或标注失败原因 |

拍摄引导：正常站立、自然呼吸，不收腹挺胸；手臂略离躯干；薄、合身、不塑形着装；避免厚外套与明显遮挡，不要求内衣/裸露。尽量固定相机和站位，避免明显俯仰与超广角近拍。无法补齐时保存草稿。

“肩宽”与“腿内长”使用明确测量示意；其定义见技术方案。全身照脸部不清楚时补充面部参考，不把模糊人脸放大当成可靠身份细节。

## 3. 功能需求与验收

| ID | 优先级 | 要求 | 验收证据 |
| --- | --- | --- | --- |
| FR01 | P0 | 新建/恢复档案、修改基本资料 | 新用户不继承测试者的数值或照片 |
| FR02 | P0 | 三类四区向导，去白模与微调 | 每步主动选择、过渡不重复触发、可返回 |
| FR03 | P0 | 四围两长独立选填 | 全空/部分/全填均可；无效值指出字段 |
| FR04 | P0 | 正侧照片导入与检查 | 方向、模糊、截断、遮挡有可理解提示 |
| FR05 | P0 | 后台估计体型与来源标记 | 输入版本和模型版本匹配；未测量不显示为实测 |
| FR06 | P0 | 三张候选，脸和体型分项确认 | 未确认不能冻结；修改参考使旧候选失效 |
| FR07 | P0 | 衣物导入与试穿回存 | 结果绑定人物、衣物、生成批次；拒绝串档 |
| FR08 | P0 | 保存恢复与删除 | 图片及参数一致；明确关联删除范围 |
| FR09 | P1 | 多场景、动作、表情 | 严肃/中性/轻微微笑可选，视线与动作符合情境 |
| FR10 | P1 | 可插拔生成服务 | 明确能力矩阵，不支持的能力禁用并说明 |
| FR11 | P2 | 衣橱分类、购买日期 | AI建议类别后用户确认/修改；购买日期可不确定 |
| FR12 | P2 | 场合/地点/天气/风格推荐 | 用户确认审美目标，解释推荐依据 |
| FR13 | P2 | 穿搭评分、批量参考图点评 | 评价服装适配而非给身体价值打分；可选择试穿 |

## 4. 状态与交互规则

用户主状态：资料草稿→外形选择完成→照片待检查→体型待确认→人物已固定→可试衣。缺照片可存草稿，不能冒充完整建档成功。

“保存选择”不是“本人认可体型”。模型内部需要带骨架A姿势，人物确认图采用普通基础衣着；不展示白模也必须让用户有机会发现错误体型。三候选需要脸/体型独立确认，均完成后才选为基准。

返回修改保留不受影响的输入；改变整体类别使局部选择需要重新确认；改变体型或面部参考使候选/人物基准进入待复核，而不是静默替换既有试穿历史。实测值和照片冲突时提示复核，不自动覆盖。

自然表现：严肃、中性、轻微微笑等可轮换，禁止夸张/极端表情。目光明确指向前方路径、镜头、正在查看的物件或交流对象；不要每张机械直视镜头。动作服务场景，身体体量不随姿势或衣服开合无故变化。

## 5. 质量与非功能要求

- NFR01 本地资料优先，外部生成前明确上传范围与服务去向；不默认公开素材。
- NFR02 后台任务不阻塞选择界面；取消/过期结果不覆盖当前版本。
- NFR03 图像输入限制大小、尺寸和格式并实际解码；存档防路径穿越与资源过量。
- NFR04 一次结果同时检查脸、体型、衣物、手部/四肢和场景合理性，不只评分画质。
- NFR05 不把固定网格拟合容差宣传为真人测量准确度，不以单人成功宣称男女胖瘦高矮通用。
- NFR06 记录候选接受率、人物保持率、衣物关键特征错误、平均尝试次数、耗时、成本；目标阈值在小样本基线之后制定，不伪造已有达标数据。
- NFR07 原始身体/脸部照片、个人模型、生成结果、缩略图和备份的删除可追溯；日志排除个人图片和密钥。

## 6. 当前事实与实施缺口

本地已实现男模五步手绘向导，11项功能检查涵盖完整选择、返回、保存恢复、过期结果、失败重试和既有人物资产不变。更早有组合几何/骨架检查，但这些不是新全流程或真实体型准确度验证。

本地原照关节点修正、候选确认和衣物导入回存已有独立能力。当前生图依赖手动对话工具交接。女性四区、四项资料与照片/可选测量的联合拟合、自动生成服务均未完成。此仓库尚不提供代码重现，后续按迁移计划引入证据。

## 7. 8周建议路线图

从实施启动算起，按一名主要开发者、可获取模板与生成服务的假设规划；不以日历到期替代验收。

| 周 | 交付 | 进入下一阶段条件 |
| --- | --- | --- |
| 1 | 现有源码和依赖梳理、许可清单、干净环境启动 | 无私人数据或绝对路径依赖，文档如实列出缺资产 |
| 2 | 基本资料→五步选择→可选尺寸→照片的统一向导 | 草稿/返回/恢复/必填边界通过 |
| 3 | 男模输入映射、照片/测量约束首版及失败提示 | 独立标记实测与估计，误差有来源 |
| 4 | 女性图库与模板路径，男女基础案例检查 | 不把男模阈值直接当女性精度依据 |
| 5 | 三候选、面部/体型确认和人物版本固定 | 修改失效与错误批次回存被阻止 |
| 6 | 单一生成提供商或可靠手动适配闭环 | 一件真实衣物从导入到回存可复现 |
| 7 | 薄厚衣物、开合、正斜侧、自然表情动作评估 | 拒绝原因可定位，体型保持有对照 |
| 8 | 小规模自愿测试、成本/延迟/隐私删除检查 | 发布已验证范围和剩余问题，决定下一阶段 |

如果模型授权、照片利用效果或提供商接入受阻，保留已可运行的手动路径，调整计划并记录原因。
