# 隐私与资产边界

即便仓库私有，也不将它用作个人照片或体型档案的存储空间。

| 资产 | 本仓库策略 |
| --- | --- |
| 项目构思、流程、去个人数据的技术方案 | 可提交 |
| 自写源码 | 后续审查后迁入 |
| 通用人体模板、权重、插画 | 明确来源/许可后再决定 |
| 真人照片、个人白模、人物底图、试衣结果 | 不提交 |
| 密钥、令牌、签名链接、个人日志 | 不提交 |
| 外部穿搭/商品图片 | 不随项目上传，来源与授权另行管理 |

.gitignore是辅助措施，不能代替提交清单审查；不得使用强制添加绕过。代码托管账户登录与产品用户数据授权是两件事。

产品设计要求：本地处理优先；外部生成前说明服务和上传素材；存储最少必要信息；每个资产关联人物/任务/版本；日志脱敏；提供原图及派生物的删除追踪；不默认将照片用于训练。具体提供商的数据条款在接入时单独核实。

如果发现私人资产误入提交，先停止继续推送并确认影响范围，再处理凭据撤销、历史清理与副本；不能只在最新提交删掉文件就声称所有副本已消失。
